## 一、规范制定的主要目的

1. **统一代码风格**：6 名成员分模块开发（blog / accounts / comments / oauth / servermanager / djangoblog），各自编码习惯不同，制定统一规范可消除风格差异、降低阅读成本。
2. **便于协作维护**：明确的命名、注释、导入与异常处理约定，让成员能快速理解他人代码，减少沟通与返工。
3. **为后续优化打基础**：第七、八周通过工具（Ruff / Flake8）发现并修复了大量风格与潜在缺陷，将有效做法固化为规范，避免问题复发。

## 二、规范的适用范围

本规范适用于本项目 `src/` 下所有应用（`blog`、`accounts`、`comments`、`oauth`、`servermanager`、`plugins`、`djangoblog`）的 Python 源码，包括：

- 业务模块、Django 视图 / 模型 / 表单 / 中间件 / 模板标签；
- 单元测试代码；
- 迁移文件（migrations）；
- 文档中引用的代码片段。

> 行宽约定：项目统一 **120 字符**（见根目录 `ruff.toml` 与 `.flake8` 的 `max-line-length = 120`）；自动生成的迁移文件允许合理折行。

## 三、规范

### 3.1 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 模块（文件名） | 小写下划线 | `oauthmanager.py`、`blog_signals.py` |
| 类名 | 大驼峰（CapWords） | `BaseOauthManager`、`OAuthUser` |
| 函数 / 方法 | 小写下划线 | `get_authorization_url`、`get_redirecturl` |
| 变量 | 小写下划线 | `access_token`、`oauth_type` |
| 常量 | 全大写下划线 | `ICON_NAME`、`DEFAULT_TIMEOUT` |
| 私有成员 | 单下划线前缀 | `_get_user_info` |

- 避免用 `type`、`list`、`id` 等 Python 内置名作变量名（本组 oauth 精读曾发现 `type` 遮蔽内置函数，已重命名为 `oauth_type`）。
- 布尔方法以 `is_` / `has_` 开头（如 `is_authorized`、`is_access_token_set`）。

### 3.2 缩进与格式

- 缩进一律用 **4 个空格**，禁止 Tab 与空格混用。
- 行宽不超过 **120 字符**，超长字符串用括号隐式拼接折行，不破坏逻辑。
- 顶层定义（类 / 函数）之间空 **2 行**，类内方法之间空 **1 行**。
- 每个 `.py` 文件末尾保留一个换行符（避免 Flake8 `W292`）。
- 运算符两侧、逗号后各留一个空格。

### 3.3 注释规范

本项目的代码精读注释统一以 **`#姓名缩写:`** 打头（张月 `#zy:`、黄梓涵 `#hzh:`、侍文博 `#swb:`、刘雨婷 `#lyt:`、谢承志 `#xcz:`、朱亮宇 `#zly:`），用于区分标注人。

- **模块级注释**：文件开头说明模块职责。例：`#xcz: 封装各第三方平台的 OAuth 授权、令牌交换和用户资料读取流程。`
- **函数 / 方法级注释**：用 docstring 说明功能、参数与返回值；标注以 `#缩写:` 开头补一句意图。例：`#xcz: 根据平台参数构造并编码第三方授权请求地址。`
- **行内 / 代码块注释**：解释“为什么”而非复述“做什么”，放在关键分支、安全校验、事务边界处。

> 说明：`#姓名缩写:` 会触发 Flake8 `E265`（井号后未留空格），这是任务要求的标识格式与 PEP 8 的规则冲突，属**预期项**，已在项目级 `.flake8` 中豁免（`extend-ignore = E203,W503,E261,E262,E265`），不计为缺陷。

### 3.4 import 规范

- import 统一置于文件顶部，按「标准库 → 第三方库 → 项目内模块」分组，组间空一行。
- 同一模块多对象导入用括号折行，禁止 `from x import *`。
- 清理未使用的导入（Ruff `F401` / `I001`）。本组 oauth 精读中曾批量修复导入排序与未使用导入。

```python
# 标准库
import json
import logging

# 第三方库
import requests

# 项目内
from oauth.models import OAuthConfig, OAuthUser
```

### 3.5 代码结构与设计

- **单一职责**：一个函数只做一件事；视图函数保持薄，业务下沉到管理器 / 服务类（如 oauth 的平台通信统一封装在 `oauthmanager.py`）。
- **抽象与复用**：公共能力抽抽象基类或 Mixin（如 `BaseOauthManager`、`ProxyManagerMixin`），遵循开闭原则。
- **高内聚低耦合**：通过 Django 信号（如 `oauth_user_login_signal`）解耦核心流程与副作用。
- **避免死代码**：删除无意义的 `if ... pass`、未使用变量（本组已清理 `views.py` 中的死代码）。
- **控制圈复杂度**：单个函数圈复杂度不超过 10（`.flake8` 中 `max-complexity = 10`），过长分支抽方法。

### 3.6 异常处理与健壮性

- **精准捕获异常**，不用裸 `except:` 或过宽异常；本组已将 servermanager 中的 `BaseException` 改为具体 `OSError`。
- **外部调用必须设置超时**：`requests.get/post` 强制 `timeout`（建议 10s），防止第三方接口挂起拖垮服务线程（oauth 待改进项）。
- **关键写操作用事务**：涉及多步数据库写入用 `transaction.atomic()`，保证一致性（oauth 的绑定流程已采用）。
- **边界处理**：缓存等外部依赖异常要兜底（servermanager 的 MemcacheStorage 已加异常兜底），不让缓存故障影响主流程。
- 日志记录用 `logging` 模块，不依赖 `print`。

### 3.7 其他约定（Django 特定）

- **模型**：字段类型选最贴近语义的类型（邮箱用 `EmailField`、链接用 `URLField`）；需要唯一约束的字段在 `Meta` 里加 `unique_together`。
- **视图**：重定向目标用 `url_has_allowed_host_and_scheme` 校验，防开放重定向漏洞。
- **Cookie 安全**：会话 / 登录 Cookie 设 `httponly=True`，防 XSS 窃取。
- **迁移文件**：历史迁移文件也需末尾换行、导入整洁，不手工篡改已应用的迁移。
- **测试**：外部依赖用 `unittest.mock.patch` 打桩隔离，不依赖真实网络 / 第三方平台。
