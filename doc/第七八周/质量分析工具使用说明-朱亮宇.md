# 质量分析工具使用说明

> 组号：8 · 编写：朱亮宇（支持经理）· 日期：2026-10-20
> 适用：第七、八周全体成员，用于自己负责 app 的代码质量分析（工具分析部分）
> 本机已验证工具：Ruff 0.17.1、Flake8 7.4.1、Pylint 4.1.3；VS Code 1.142.0

---

## 0. 一分钟准备

```bat
:: 1) 先 cd 到你自己的项目根目录（里面能看到 src/，以及 venv 或 .venv）
cd /d 你的项目路径

:: 2) 确认虚拟环境目录名（Windows 用 dir；Linux/macOS 用 ls）
dir

:: 3) 激活虚拟环境：按你的目录名，只运行其中一条
::    如果你的目录叫 venv：
venv\Scripts\activate
::    如果你的目录叫 .venv：
.venv\Scripts\activate

:: 4) 把工具装进当前虚拟环境
python -m pip install ruff flake8 pylint
```

- 用 **VS Code 打开项目根目录**（不是 `src`），这样 `ruff.toml`、`.flake8`、`.vscode/settings.json` 才会生效。
- 右下角解释器选**项目虚拟环境里的 python**：`venv\Scripts\python.exe` 或 `.venv\Scripts\python.exe`（按你的目录名）。
- 如果你本地虚拟环境目录叫 `.venv`，请把 `.vscode/settings.json` 里的 `${workspaceFolder}/venv/Scripts/python.exe` 改成 `${workspaceFolder}/.venv/Scripts/python.exe`。
- 本次已在仓库根目录新增统一配置：`ruff.toml`、`.flake8`、`.vscode/settings.json`、`.github/workflows/code-quality.yml`。

> ⚠️ **虚拟环境目录名各人可能不同：本机是 `venv`，有的同学是 `.venv`。** 先 `dir` / `ls` 看一眼，把包装进你自己的那个环境，不要装到系统 Python。
>
> 保险写法（把 `venv` 换成你实际的 `.venv`）：
> ```bat
> venv\Scripts\python.exe -m pip install ruff flake8 pylint
> venv\Scripts\python.exe -m pip show ruff
> ```
> `Location` 显示 `...\<你的项目>\venv\Lib\site-packages`（或 `.venv\Lib\site-packages`）就说明装对了。


> Ruff / Pylint / Flake8 的 **VS Code 扩展**（`charliermarsh.ruff`、`ms-python.pylint`、`ms-python.flake8`）是编辑器前端，组长清单没强制要求；装了才能在 VS Code 里实时看波浪线，建议一起装。

## 1. VS Code 里装什么、怎么看

### 1.1 需要安装的扩展

| 扩展 | 扩展 ID | 作用 |
|---|---|---|
| Python | `ms-python.python` | Python 语言支持、选择解释器、运行/调试 |
| Pylance | `ms-python.vscode-pylance` | 类型检查与智能提示（装 Python 扩展时会自动带） |
| Ruff | `charliermarsh.ruff` | **主力**：实时检查 + 自动修复，速度快 |
| Pylint | `ms-python.pylint` | 补充检查：命名、复杂度、设计告警 |
| Flake8（可选） | `ms-python.flake8` | 兼容老习惯；已装但默认关闭，避免与 Ruff 重复告警 |

命令行安装（已装可跳过）：

```bat
code --install-extension ms-python.python
code --install-extension charliermarsh.ruff
code --install-extension ms-python.pylint
code --install-extension ms-python.flake8
```

### 1.2 单文件实时检查怎么看

1. 打开任意 `.py` 文件，代码下方会出现**波浪线**；鼠标悬停可看规则码和说明。
2. 打开「问题」面板：`Ctrl+Shift+M`（或点击底部状态栏的 ✖/⚠ 图标），可按文件/严重级别筛选。
3. 底部「问题」面板会显示：`规则码`、`行:列`、`问题描述`，例如 `F401 'os' imported but unused`。
4. Ruff 没反应时：`Ctrl+Shift+P` → 输入 `Ruff: Restart Server`。
5. Pylint 没反应时：`Ctrl+Shift+P` → 输入 `Python: Run Linting`。
6. 想临时只留一个工具：在 `.vscode/settings.json` 把 `pylint.enabled` 或 `ruff.enable` 改为 `false`。

> 当前工作区默认：**Ruff 开、Pylint 开、Flake8 关**。三者规则有重叠，全开会出现重复波浪线；命令行仍可分别运行。

## 2. 命令行跑整个项目

在项目根目录、已激活项目虚拟环境的终端执行（PowerShell / CMD / Git Bash 均可）：

```bat
:: 全项目
ruff check .
flake8 .

:: 只跑自己负责的 app（把 blog 换成自己的 app）
ruff check src\blog
flake8 src\blog

:: 按规则汇总（写报告时最好用这个）
ruff check src\blog --statistics
flake8 src\blog --statistics

:: 保存结果到文件，方便截图/贴报告
ruff check src\blog --statistics > ruff-blog-before.txt 2>&1
flake8 src\blog --statistics > flake8-blog-before.txt 2>&1
```

常用参数：

| 命令 | 用途 |
|---|---|
| `ruff check . --output-format=concise` | 一行一条，适合终端截图 |
| `ruff check . --output-format=github` | GitHub Actions 注释格式 |
| `ruff check . --fix` | 自动修复**安全**问题（改前先 commit 或 stash） |
| `ruff check . --fix --unsafe-fixes` | 连同“不安全”修复一起做，**必须逐条 review** |
| `ruff check . --select DJ` | 额外检查 Django 专项规则（可选） |
| `pylint src\blog --max-line-length=120 --ignore=migrations` | Pylint 全量检查（较慢） |
| `pylint src\blog --max-line-length=120 --ignore=migrations --disable=C0114,C0115,C0116` | 先关掉“缺文档字符串”告警，聚焦错误/命名/复杂度 |

说明：

- 退出码 `0` = 没发现问题；`1` = 发现问题。看到 `Found N errors` 就说明工具跑通了。
- 默认排除 `venv`、`migrations`、`src/frontend`、`src/locale`、`src/logs`（配置见 `ruff.toml` / `.flake8`），避免自动生成代码产生大量噪声。
- 行宽统一按 **120** 字符；团队统一用这个口径，报告里好对比。

## 3. 常见质量问题分类怎么看

Ruff 输出里的 `[*]` 表示**可用 `--fix` 自动修复**；没有 `[*]` 的需要手工改。

| 类别 | 典型规则码 | 含义 | 处理建议 |
|---|---|---|---|
| 命名 | `N801` `N802` `N806` `invalid-name` | 类/函数/变量不符合 PEP8（如类名小写） | 能改则改；涉及模型/迁移的先记录 |
| 未使用 | `F401` `F841` `F811` | import 未使用、变量赋值未使用、重复定义 | `ruff --fix` 可自动删 import/变量 |
| 代码风格 | `E501` `E261` `E302` `W291` `W293` | 行太长、注释空格、空行、行尾空格 | 多为 `--fix` 可修 |
| import | `I001` `F403` `F405` | import 未排序、`import *`、星号导入导致未定义 | `ruff --fix`；`import *` 手工拆开 |
| 复杂度 | `C901`（flake8）/ `PLR0912` `PLR0915`（pylint） | 函数圈复杂度过高、分支/语句过多 | 拆函数，报告里记为“待重构” |
| 异常处理 | `BLE001` `E722` `B904` | 捕获过宽、裸 `except`、raise 未 from | 收窄异常类型；至少记录日志 |
| 可简化 | `UP032` `C417` `SIM*` | 可用 f-string/推导式/更简写法 | `ruff --fix` 可处理大部分 |
| 潜在 bug | `B*`（bugbear） | 可变默认参数、循环变量未用等 | 逐条人工确认 |
| Django 专项 | `DJ*` | 如 `DJ001`：CharField 允许 null | 用 `--select DJ` 单独跑 |

> 写报告时建议按「规则码 + 数量 + 代表文件/行 + 是否修复」记录，不要只贴一张总数截图。

> Pylint 对 Django ORM 的 `.objects` 可能报 `E1101 no-member`，这是未加载 Django 插件时的**已知误报**；可在命令后加 `--disable=E1101`，或在报告里注明“误报，不计入修复”。

## 4. GitHub Actions 项目检查（已配置）

仓库已新增 `.github/workflows/code-quality.yml`：

- 触发：每次 `push`、`pull_request`，也可在 Actions 页手动 `Run workflow`；
- 环境：Ubuntu + Python 3.12；
- 步骤：安装 `ruff flake8` → `ruff check . --output-format=github` → `flake8 . --statistics`；
- 两个检查都设了 `continue-on-error: true`：**不会把流水线卡红**，但问题会以 annotation 形式标在 Actions 页和代码行上。

查看方式：

1. 打开 GitHub 仓库 → **Actions** 标签；
2. 左侧选 **Code Quality** → 点最新一次运行；
3. 点 `lint` job，展开 `Ruff check` / `Flake8 check` 查看日志；
4. `Ruff check` 里的 `::error file=...` 会直接显示在对应文件行上（Annotations）。

说明：

- 如果仓库没显示 Actions，去 **Settings → Actions → General** 选 `Allow all actions and reusable workflows`。
- 想让检查失败就阻断合并：把 `continue-on-error: true` 删掉即可。
- 本机也可以先跑 `ruff check .` / `flake8 .` 预演，CI 结果应与本地一致（依赖 `ruff.toml` / `.flake8`）。

## 5. 各 app 负责人拿到后怎么操作

以 `blog` 为例（换成 `accounts` / `comments` / `oauth` / `servermanager` / `djangoblog`）：

1. **同步代码**：`git fetch origin && git checkout 你的分支 && git merge origin/master`
2. **装工具**：项目根目录先激活自己的虚拟环境（`venv\Scripts\activate` 或 `.venv\Scripts\activate`），再 `python -m pip install ruff flake8 pylint`（装进当前虚拟环境，不是全局 Python）
3. **跑修复前基线**：
   ```bat
   ruff check src\blog --statistics > ruff-blog-before.txt 2>&1
   flake8 src\blog --statistics > flake8-blog-before.txt 2>&1
   ```
4. **截图**：①VS Code 打开自己 app 的某个文件 + 问题面板；②终端 `ruff check` / `flake8` 输出。
5. **修复**：
   ```bat
   ruff check src\blog --fix
   ruff check src\blog --statistics > ruff-blog-after.txt 2>&1
   flake8 src\blog --statistics > flake8-blog-after.txt 2>&1
   ```
   手工修 Pylint/复杂度过高的问题；改完重新跑一遍。
6. **截图修复前后对比**：`ruff-blog-before.txt` vs `ruff-blog-after.txt`，以及 1-2 组代码 diff。
7. **群里汇报**（统一模板）：

```text
【第七八周工具分析】姓名 - app
工具：ruff 0.17.1 / flake8 7.4.1 / pylint（可选）
命令：ruff check src\<app> --statistics
修复前：ruff N 个，flake8 M 个
已修复：ruff a 个（--fix 自动 x 个 + 手工 y 个），flake8 b 个
未修复：c 个（原因：涉及模型改名/迁移风险/需重构）
截图：已传钉钉「第七八周/姓名」
```

8. **截图归档**：钉钉群「第七八周」→ 自己名字的子文件夹，文件名建议 `工具分析-<app>-before.png`、`工具分析-<app>-after.png`。
