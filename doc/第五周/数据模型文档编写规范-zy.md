## 二、表结构表格式规范

每个实体表用一张 Markdown 表格描述，**列固定为五列**：`字段 | 类型 | 主键 | 外键 | 说明`。

| 要素 | 要求 |
|---|---|
| 字段名 | 与 `SHOW CREATE TABLE` / `models.py` 完全一致（注意命令类 model 有小写类名，如 servermanager 的 `commands`） |
| 类型 | 以朱亮宇《数据库表结构导出（最终版）.md》为准（如 `bigint`、`varchar(50)`、`datetime(6)`、`tinyint(1)`） |
| 主键 | 主键列打 ✅，其余留空 |
| 外键 | 外键列打 ✅，并在说明中注明「外键 → <目标表>.<字段>」；无外键则留空 |
| 说明 | 一句话中文说明；Django 自动字段（`auto_now_add`/`auto_now`/`default=now`）注明自动维护语义；`BooleanField` 注明「布尔 0/1、默认 False/True」 |

表格分隔行统一用 `| ---- | ---- | ... |`（与 servermanager 部分保持一致）。

## 三、model 对应说明格式

每个实体表下方紧跟一行加粗的 **`model 对应`**，格式固定：

> **model 对应**: <类名> — 数据：<存储什么数据>；职责：<承担什么职责>；<关系重数说明或无外键说明>。

- 「数据」说明该实体存储的业务对象；「职责」说明在系统中的作用及由谁写入/读取。
- 有外键的实体，必须写清关系重数与关系名（见第四节）。
- 无外键的独立表，显式注明「无外键，与其它实体无关联、无关系重数」。

---

## 四、关系重数标注规范

关系重数统一采用 `A : B` 记法，即「实体侧 : 被引用侧」：

| 记法 | 含义 | 示例 |
|---|---|---|
| 1 : 1 | 一对一 | —— |
| 1 : N | 一对多（被引用侧为 1） | blog_article.category → blog_category（N:1） |
| N : M | 多对多 | blog_article ↔ blog_tag（经中间表 blog_article_tags） |
| 0..1 : 1 | 可选绑定（引用侧允许为空） | oauth_oauthuser.author → accounts_bloguser（第三方账号可选绑定本地用户） |
| 0..N : 1 | 自关联 / 可空多对一 | comments_comment.parent_comment（楼中楼） |

> 跨 app 外键必须覆盖模板 3.1 节列出的 8 条关系，不得遗漏。

## 五、命名与术语规范

- 实体表名、字段名、model 类名一律沿用源码实际拼写（不另造别名）。
- 类名大小写以 `models.py` 为准（如 `OAuthUser`、`OAuthConfig`、`commands`）；发现代码命名不规范先反馈，不改文档迁就。
- 中文说明与源码 `verbose_name` 保持一致（如 `commands.title` 的 verbose_name 为「命令标题」）。
- 平台类型、字段含义等术语全文统一，避免同一概念多种叫法。

## 六、Markdown 格式规范

- 表格列对齐、分隔行完整，标题层级 `#`/`##`/`###`/`####` 逐级下降不跳级。
- 加粗使用 `**`，代码/类名/字段名使用反引号 `` ` ``。
- 每个分节文件末尾附「实体与 model 的对应关系汇总」中自己 app 的行，供组长 3.3 节整合。
- 不插入未经组内确认的截图或超链接；E-R 图由黄梓涵统一绘制，各分节不自行放图。
