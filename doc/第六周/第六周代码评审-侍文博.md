## 二、评审发现与修改建议

### 1. oauth：AppConfig 注释提到的启动初始化在类中没有实现

- **位置**：`src/oauth/apps.py:1`，`72fd08e`。
- **现状**：模块文档字符串称 `OauthConfig`“负责应用级配置与启动初始化”；类中仅设置 `name = 'oauth'`，没有覆写 `ready()` 或执行初始化逻辑。
- **问题**：读者可能据此认为 oauth 应用启动时会由该配置类执行额外初始化，而当前实现没有这条启动行为。
- **建议**：将说明收窄为“定义 oauth 应用的 Django 配置”；若以后增加启动初始化，再在对应方法和注释中描述。
- **性质**：本周新增注释准确性，P2。

### 2. comments：测试文件头把未验证的回复级联行为列为覆盖内容

- **位置**：`src/comments/test_comment_business_logic.py:10`，`837aeec`；对应 `CommentDeletionTest.test_deleting_parent_comment_with_replies()`。
- **现状**：文件头列出“评论删除（含父评论与回复的级联行为）”。用例断言父评论被删除，但对回复仅保留“如果是 CASCADE / SET_NULL”的说明，没有断言回复实际被删除或其父级被置空。
- **问题**：文件头会让读者误以为测试已经验证回复删除时的级联结果，实际测试没有确定该行为。
- **建议**：将文件头改为“父评论删除场景（回复级联结果尚未断言）”；如果确需覆盖级联，按模型的 `on_delete` 预期补充明确断言。
- **性质**：本周新增注释准确性 / 测试覆盖范围说明，P2；不表示本次评审已验证数据库级联行为。

### 3. servermanager：`send_result=False` 的注释把默认值直接解释成发送失败

- **位置**：`src/servermanager/migrations/0001_initial.py:41`，`406a958`。
- **现状**：字段定义为 `BooleanField(default=False)`，新增注释称默认 `false`“代表发送失败”。模型文档只说明该字段记录发送是否成功，迁移本身没有表达发送尝试状态或失败状态枚举。
- **问题**：布尔默认值只能说明新建记录初始为 `False`；仅从字段定义不能推断记录已经尝试发送且失败。将默认值等同失败会掩盖“尚未写入成功结果”等可能状态。
- **建议**：改为“默认值为 False，表示尚未标记为发送成功”；若业务确实区分未发送、发送中、失败和成功，应由对应业务流程与状态定义说明。
- **性质**：本周新增注释准确性，P2。

### 4. servermanager：`assertIsNotNone()` 的“内容不为空”表述由主审记录覆盖

- **位置**：`src/servermanager/tests.py:22`，`406a958`。
- **现状 / 建议**：新注释把 `self.assertIsNotNone(content)` 说成“返回内容不为空”。该断言只排除 `None`。此项与主审 R3 相同，按主审建议修改为“断言返回值不是 None”，本记录不另计一项。
