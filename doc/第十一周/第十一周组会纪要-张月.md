## 二、实践总结讨论

**做得好的方面：**

- 分工明确：每人固定负责一个 app 模块，职责清晰、交叉改动少；
- 组长统一分支合并 + PR 评审，master 分支始终可用；
- 任务跟踪表 + 组会纪要全程同步进度，截止时间明确；
- 统一文档/代码规范（编码规范、注释带 `#缩写:`、报告模板），整合成本低。

**遇到的困难与不足：**

- 多人协作时出现合并冲突与误覆盖（如 readme.txt、md 文件被覆盖），需组长逐一核对；
- 本地环境不一致：.env 环境变量未自动加载导致 MySQL 1045 密码错误；
- 个别误提交 node_modules、嵌套仓库引用等无关/超重文件，造成仓库膨胀与返工；
- 演示视频原始文件超 100MB，需压缩后提交；代码量统计口径不统一，维护报告数据反复调整。

## 三、后续改进建议

- 任务分工第一周即确定并固定，避免后期功能点撞车；
- 制定统一规范（编码规范、代码标注格式、报告模板）并严格执行；
- 视频、大文件等素材走网盘/钉钉传输，仓库只放压缩后的最终版本；
- 每次组会产出可落地的待办清单并写入任务跟踪表，明确责任人与截止时间；
- 继续强化 git 分支协作流程（功能分支 + Pull Request + 评审）。
