# 第九、十周维护代码量统计口径（模板）

> 制定人：朱亮宇（支持经理）
> 用途：统一全组「维护代码量」统计口径，供《开源软件维护报告》第 7 章使用。
> 使用方法：各成员按本口径统计自己本次维护的改动，填「二、汇总表」自己那一行，**11-11 前**回传朱亮宇汇总。

---

## 一、统计口径说明（各成员照此数）

| 统计项 | 口径定义 |
|---|---|
| **新增文件** | 本次维护新增的 `.py`（及必要模板/静态文件），不含自动生成文件（`__pycache__/`、migrations 自动迁移、`*.pyc`） |
| **修改文件** | 本次维护改动过的已有文件（只改动 1 行也算 1 个修改文件） |
| **新增行数** | 新增文件中新增的代码行；或修改文件中纯新增的行 |
| **修改行数** | 修改文件中被替换/删除的行（对应 `--numstat` 第二列）；纯新增的行只算新增行，不算修改行 |
| **受影响行数** | **新增行数 + 修改行数**（即 `--numstat` 第一列 + 第二列；报告第 7 章表 4「受影响的代码行数」直接用这一列，不用再手算） |
| **功能点** | 一个可独立描述的新增功能或缺陷修复 |

### 统计窗口（重要）

- **基线**：以 `origin/develop` 为基准，只统计**本次维护（第九、十周）自己提交**的改动；
- **不算**：merge 带进来的他人代码、第七八周的代码标注（`#zy:` 等注释）、自动生成文件；
- **行数口径**：按 `git diff --numstat` 的物理行数统计（含注释、空行），保证大家数出来的能对上。

### 建议统计方法（命令行，二选一）

1. **对比合并前后**（推荐，能自动算行数）：
   ```
   # 在你自己的分支上，对比你分支相对 develop 的改动
   git diff origin/develop...你的分支名 --stat
   git diff origin/develop...你的分支名 --numstat
   ```
   `--stat` 看每个文件 ±行数，`--numstat` 第一列 = 新增行、第二列 = 删除/替换行；**受影响行数 = 第一列 + 第二列**。

   > 三点 `...` 表示以两边共同祖先为基准，merge 过 develop 的分支也只会显示自己的改动，不会把 develop 的代码算进来。

2. **GitHub 网页**：自己分支的 Pull Request / Commits 页面，看每个文件 `+N −M` 的数字。

## 三、汇总后怎么进报告第 7 章（朱亮宇）

1. **表 4 列**：序号 | 维护类别（新增功能/修改缺陷）| 名称 | 受影响的代码行数 | 负责维护的组员；最后一行合计“N 个维护项 / M 行”。

3. **备注**：复用已有字段、改动很少的功能点，在表后备注说明，避免“功能点多但行数为 0”被质疑。
