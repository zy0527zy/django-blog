## 七、Git 与协作约定

- **分支**：`姓名首字母_branch`，push 到自己分支（不 push develop / master）。
- **commit 命名**：
  - 功能代码 → `姓名 第九十周功能修改 <app> <功能点>`
  - 报告/类图 → `姓名 第九十周维护报告 <app>`
- **文件命名**：
  - 维护报告板块 → `开源软件维护报告-<部分>-<姓名>.md`
  - 维护后类图 → `doc/第九十周/StarUML工程-<姓名>/<app>-维护后.uml`（导出 PNG 一并提交）
- **注释标识**：新增代码注释带 `#姓名缩写:`（zy / hzh / swb / lyt / xcz / zly），便于区分谁写的代码。
- **合并规则**：张月审核（走 PR）通过后合入 develop；develop 定稿后张月合并到 master。
- **图片**：报告配图 / 界面原型 / 类图导出 PNG，放 `doc/第九十周/imgs/`，文件名用英文（如 `blog-hot-hzh.png`），md 里用相对路径 `![](imgs/xxx.png)`。
- **编码规范**：新增/修改的代码必须遵守第七、八周定稿的《编码规范-谢承志.md》。
