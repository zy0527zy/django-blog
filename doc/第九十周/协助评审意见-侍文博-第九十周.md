# 第九、十周协助评审意见（侍文博）

> 主审：黄梓涵
> 协助评审：侍文博（开发经理·协助）
> 评审范围：第九、十周六个子系统维护代码（blog、comments、djangoblog、oauth、servermanager；accounts 为本人负责模块，不在本文复核）
> 评审方式：依据合并后的 develop 源码、维护报告板块、测试记录与类图材料进行静态复核。除报告已提供的测试证据外，不声称独立重新执行了全部测试。

## 一、总体意见

本轮维护在六个子系统上共落地约 13 个功能点，多数沿用 Django 既有机制（中间件、ModelForm、Admin、ORM、插件钩子）而非重造架构，整体方向合理。安全敏感路径（维护模式放行、评论删除权限、统计面板权限、OAuth 回调地址）已有针对性处理，但仍建议在回归测试中重点覆盖。

## 二、分模块复核

### 2.1 djangoblog（张月）

维护模式通过 `MaintenanceModeMiddleware` 统一拦截，配合白名单放行 `/admin`、静态资源与健康检查，避免把管理员锁在门外；公告栏经 `seo_processor` 注入模板，空值不显示，设计清晰。`handler403` 拼写修正与 `handler400` 补充顺带修复了一个真实缺陷，属于有价值的顺带整改。

建议复核：维护模式白名单是否覆盖 `/media`、`/static` 与健康检查路径；公告栏依赖 `seo_processor` 缓存，修改公告后需确认缓存已失效。

### 2.2 blog（黄梓涵）

阅读量通过事务 + `F` 表达式更新，周统计用「文章 + 周起始」唯一约束避免重复记录；置顶复用 `article_order` 字段，批量更新后主动清缓存。上述设计避免了重复字段和并发计数丢失。53 项相关测试通过，覆盖较好。

建议复核：批量置顶的缓存清理是否覆盖首页列表、侧栏与详情页三处引用；周统计的自然周起点计算与站点时区是否一致。

### 2.3 comments（刘雨婷）

评论删除要求登录 + POST + CSRF，服务端二次校验作者/管理员身份，父评论删除沿用外键级联；置顶仅允许工作人员操作公开顶层评论，普通用户与楼中楼回复被拒绝。47 项测试通过，且补充了真实 HTTP 表单操作与缓存核对，验证较扎实。

建议复核：删除/置顶后的缓存清理是否覆盖文章评论数与侧栏；`is_top` 字段与迁移是否对既有数据默认值为 `False`。

### 2.4 oauth（谢承志）

Gitee 登录通过 `GiteeOauthManager` 复用 `BaseOauthManager` 接入，字段取值用 `dict.get()` 与空值回退，结构与其他平台管理器一致。GitHub 回调地址不再拼接 `next_url`，直接使用后台配置的 `callback_url`，与平台校验一致。

建议复核：`BaseOauthManager.do_get/do_post` 仍会记录第三方响应全文，若响应中含令牌/授权码存在日志泄露风险，建议后续加脱敏；请求仍缺少显式超时，网络异常时可能悬挂。

### 2.5 servermanager（朱亮宇）

统计面板由 `SiteStatisticsService` 只读聚合、视图仅限超级管理员，权限边界清晰；邮件重试将逻辑收敛到 `EmailService`，后台操作与管理命令复用同一实现，避免重复。9 个单元测试覆盖权限、成功/失败、空收件人、批量与管理命令，成功路径用 mock 覆盖。

建议复核：邮件重试的并发与幂等（同一条失败记录被并发触发时是否可能重复补发）；管理命令 `--limit` 与实际取数是否一致。

## 三、跨模块改进建议

1. 安全敏感路径（维护模式放行、评论删除/置顶权限、统计面板权限、OAuth 回调）建议各补一条隔离回归测试，明确「未授权应被拒绝」。
2. 缓存失效是各模块共性问题，建议统一说明「哪些缓存键在哪些操作后失效」，避免遗漏。
3. 各模块代码量按统一口径（扣除自动迁移）上报，与第 7 章汇总一致。

## 四、协助评审结论

各模块维护内容与分工对应，测试与代码量材料基本齐全，安全边界已有处理。建议结论为「协助评审通过，个别安全与并发项留待回归验证」，不替代教师验收与完整部署测试。
